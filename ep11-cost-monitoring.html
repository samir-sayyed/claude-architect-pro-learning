01 / UNDERSTAND

Five ideas worth keeping.

Unit economics explain what a growing total bill cannot.

A bill can rise because request volume grows, request mix changes, or each request becomes more expensive. Separate token buckets and track cost by request type. Relate spend to useful outcomes so retries and rework do not disappear from the analysis.

↗ Lesson 5:00

Cache health depends on prefix stability and traffic.

Dynamic fields early in the prompt, ordering changes, configuration drift, and expiry can reduce reuse. Inspect cache reads and writes rather than assuming a cached system remains healthy. Cache-read share of input tokens is different from the fraction of requests with a hit.

↗ Lesson 17:00

Tier and trim only while preserving the quality floor.

Move proven easy slices to lower-cost capability and remove irrelevant fields or history. Reduce retrieval depth with evidence from evaluations, not a blanket cut. Output caps need checks for truncation; a shorter answer is not automatically complete.

↗ Lesson 21:00

Batch work that genuinely tolerates asynchronous completion.

Independent overnight jobs can fit a batch API; an interactive user or a dependent tool loop usually needs a different path. Keep a durable request-to-result mapping using unique identifiers. Batch submission does not automatically execute a multi-turn tool workflow.

↗ Lesson 29:00

Monitor cost and drift even when you deploy nothing.

Watch cost per type, token composition, cache reuse, tail latency, errors/refusals, volume, and quality. Query mix, documents, and provider behavior can change without an application release. Scheduled golden-set checks and controlled migrations help expose that drift.

↗ Lesson 61:00
02 / DECIDE

Make the tradeoff visible.

Four levers, each with a condition

LeverUse whenProtect against
Prefix cachingStable material repeats within reuse conditionsDynamic fields and expiry
Model tieringA task slice passes its quality gateHidden hard-case regressions
Context reductionFields or chunks add no needed evidenceRemoving essential facts
Asynchronous batchThe job can wait and is independently executableBreaking interactive or dependent work

A cost investigation that preserves quality

  1. Separate volume from unit cost
  2. Inspect token buckets by task
  3. Locate prefix or context drift
  4. Apply one eligible lever
  5. Rerun quality and latency gates
  6. Monitor the new unit economics

03 / WORKED EXAMPLE · FROM THE LESSON

Cache reuse collapses while quality stays flat

The lesson’s cache-health scenario drops from roughly 70% reuse to zero. Evaluation quality is unchanged, so the failure is economic rather than evidence of weaker reasoning.

THE TEMPTING MOVE

Use a larger model, retrieve more documents, or move every request to batch processing.

THE BETTER-FITTING MOVE

Compare the serialized prefix. Move the variable greeting out of the reusable region and confirm that cache-read usage returns while quality and latency remain acceptable.

The first investigation should match the changed signal. A dynamic prefix explains cache collapse more directly than model capability does.

DETAIL 02

Use trace metadata to explain an economic regression

Episode 08’s logging checklist adds prompt/config and index versions, per-step durations, token buckets, tool outcomes, and retries. When cost rises, separate request volume, workload mix, route selection, output length, and cache behavior. A drop in reads suggests inspecting prefix and reuse conditions; stable cache usage with longer outputs suggests a different cause. Keep quality and tail latency beside the cost graph.

DETAIL 03

Include the cost of evaluating the system

The Episode 09 runner counts extraction and judge usage together in its estimate. Keep operational inference cost and evaluation cost visible as separate categories so sampled judging does not look like unexplained application inflation.
