Treat context as a budget, not a warehouse.

Use examples to calibrate judgment, place evidence deliberately, and keep reusable prompt material stable. Cache reuse applies to a prefix, not to the whole answer.

01 / UNDERSTAND

Five ideas worth keeping.

Add examples when they clarify a real ambiguity.

A simple task may need only an explicit instruction. A few carefully selected examples help with formatting and difficult boundary judgments. Prefer varied cases, including edge cases, over a large collection of near-duplicates. Examples guide behavior; they do not guarantee it.

↗ Lesson 11:00

A large context window does not make every token useful.

Irrelevant fields, verbose tool results, and repeated history compete with the evidence that matters. Budget instructions, examples, retrieved material, and output deliberately. Trim or summarize intermediate content while checking that essential facts survive.

↗ Lesson 20:00

Placement can affect whether important evidence is used.

The lesson describes lost-in-the-middle failures and recommends deliberate ordering: stable instructions early, relevant context close to the task, and a clear final question. Test placement on your workload rather than treating one ordering as universal.

↗ Lesson 22:00

Prompt caching reuses a stable prefix, not a previous answer.

Separate reusable tools, instructions, and examples from dynamic documents and queries. A cache read can be cheaper than processing the same input again, while writes and expiry affect the economics. Fresh input and generated output still have their own costs.

↗ Lesson 33:00

Progressive disclosure reduces irrelevant context.

Always-applicable guidance and on-demand skill bodies serve different purposes. Keep the small discovery description available and load detailed instructions when relevant. Deferring content reduces prompt load; it does not remove a capability or its authorization requirements.

03 / WORKED EXAMPLE · FROM THE LESSON

A cached prefix is only part of the bill

The lesson illustrates a request with 2,800 stable tokens and 3,000 fresh tokens. Only the stable portion is a candidate for cross-request reuse.

THE TEMPTING MOVE

Assume a large discount on cached reads means the entire request becomes equally cheaper.

THE BETTER-FITTING MOVE

Account separately for the stable prefix’s writes and reads, the fresh input, and the generated output. Check traffic frequency and expiry before forecasting savings.

A large percentage saving on one bucket can be a modest saving on the complete workload.

DETAIL 01

Design examples and context as a shared budget

Few-shot examples should teach the desired format and difficult judgments, especially ambiguous or absent-evidence cases. Stable examples can sit with reusable instructions. Budget system instructions, examples, retrieved material, the request, and space for the answer. Test whether important evidence is actually used; context placement is a hypothesis to evaluate, not a guarantee about every model.

DETAIL 02

Arrange layers by how often they change

Put reusable material before request-specific content when the provider’s caching mechanism permits it. The deck orders tools, instructions and examples, background material, then the user request. Background documents are reusable only while the exact relevant prefix remains stable. Compare serialized prefixes when reads disappear; timestamps, tool order, configuration changes, and expiry are useful suspects.

DETAIL 03

Work through the cache arithmetic

Use the episode’s 5,800-token example: 2,800 stable tokens and 3,000 fresh tokens. At an illustrative cache-read multiplier of 0.1, a warm hit costs the equivalent of 2,800 × 0.1 + 3,000 = 3,280 fresh input tokens. The input-only saving is 2,520 ÷ 5,800 ≈ 43.4%. This excludes writes, misses, output, tools, and infrastructure; it does not establish the deck’s monthly bill or a 43.4% total saving.

DETAIL 04

Separate reuse of instructions from reuse of computation

An on-demand skill controls which task instructions enter context. Always-loaded project rules serve common obligations. Prompt caching prices repeated eligible input differently; it does not make the instruction relevant or replace an authorization check. Keep shared policy concise and load specialized procedures when needed. Exact skill frontmatter and cache thresholds are product-specific.
