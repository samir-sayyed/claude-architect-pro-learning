ITEM 01 · Q15 · DOMAIN 2 · OBJECTIVES 2.4

Preserving state during context reduction

A long-running investigation accumulates large tool outputs. Near the context limit, the system drops the oldest messages. It then repeats already rejected hypotheses and forgets the user’s no-contact restriction. The complete evidence must remain available for audit, but need not all be active in every call. What is the BEST redesign?

Correct: A · select 1

Compaction should preserve decisions and constraints, not just recency. Audit storage and the active context window serve different purposes.

  1. A · Correct

    Persist goals, constraints, decisions and evidence references; compact verbose history and retrieve raw evidence as needed.

    Critical state remains explicit while audit evidence need not occupy every call.

  2. B · Distractor

    Summarize the tool outputs into a short narrative after each step, discard identifiers and validate summary readability before continuing.

    Readability is not faithful state preservation; losing identifiers weakens evidence lookup and audit linkage.

  3. C · Distractor

    Keep a fixed sliding window and prepend the original request; retain complete raw history in audit storage for later investigation.

    It preserves the original restriction but can still lose intermediate rejected hypotheses and decisions.

  4. D · Distractor

    Select a larger-context model and retain the current oldest-message eviction rule, testing only average task completion before rollout.

    It postpones the failure and does not establish preservation of critical constraints during eviction.

ITEM 02 · Q21 · DOMAIN 3 · OBJECTIVES 3.2

Valid authentication establishes who is calling; authorization determines what that identity can access. Derive or validate tenant scope in trusted server logic.

    Check each report lookup against server-side caller membership and resource permissions.

    The missing control is authorization for the requested tenant resource.

  4. D · Distractor

    UI scoping does not enforce the server boundary against altered requests.

ITEM 03 · Q04 · DOMAIN 1 · OBJECTIVES 1.4, 1.5
