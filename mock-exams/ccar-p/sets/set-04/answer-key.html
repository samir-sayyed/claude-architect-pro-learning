A team adopts a coding assistant and sees pull requests produced faster. Review time increases because generated changes are broad, tests are often unrelated and maintainers struggle to understand design intent. Release lead time is unchanged. The team wants useful productivity rather than more generated code. Which workflow change BEST addresses the observed bottleneck while preserving maintainers' responsibility for the codebase?

Correct: B · select 1

Optimize the end-to-end delivery process and reviewability, not a local drafting-time metric.

  1. A · Distractor

    Increase the assistant's parallel coding sessions and count completed pull requests per engineer to reflect the improvement in generation throughput.

    More output can worsen the review queue.

  2. B · Correct

    Scope reviewable changes with explicit acceptance checks, measuring review effort and merge lead time alongside coding time.

    This targets the downstream review bottleneck.

  3. C · Distractor

    Require longer generated explanations and complete snapshots of changed files so reviewers receive more material with every pull request.

    More material does not ensure focused reviewability.

  4. D · Distractor

    Allow the assistant to approve its own changes after passing tests, using maintainer review only for files that recently caused incidents.

    Test success does not transfer maintainer authority.
