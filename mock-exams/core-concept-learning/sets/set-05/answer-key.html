Q1 · Move the calculation boundary before the pilot

Select 1.

A tunnel survey team proposes a model that converts surveyor notes into both a narrative and a clearance verdict. Clearance is defined by a published deterministic formula using calibrated sensor readings. Reviewers can approve narratives, but the automated verdict immediately releases equipment and cannot wait for review. A prototype reproduces ninety-nine historical verdicts correctly. Which architectural recommendation BEST addresses the fit of this proposed release boundary?

  1. Correct. Keep clearance in validated calculation code and evaluate a separate, source-linked narrative assistant under the existing review process.

    The release requires exact reproducible computation without review; strong historical agreement does not justify moving that boundary into generation.

  2. Incorrect. Convert the formula into few-shot worked examples and restrict outputs to the two allowed clearance verdict labels.

    Examples and constrained labels improve presentation but still leave the critical calculation to probabilistic generation rather than validated code.

  3. Incorrect. Use the historical prototype as a release filter, escalating only survey notes unlike those in the ninety-nine examples.

    Similarity to observed notes cannot establish the correctness of a new safety-relevant numeric calculation or its unreviewed release.

  4. Incorrect. Retain model-generated verdicts but require two independently worded prompts to agree before the automatic equipment release proceeds.

    Agreement can repeat a shared computational mistake and does not establish the formula execution guarantee required at the release boundary.

The fit decision concerns the consequence and mechanism, rather than a favorable aggregate score. Preserve exact clearance computation in code and use language generation for the reviewable explanation. The historical test remains useful evidence for that narrower assistant, not authorization to replace the release calculation.

Q2 · Establish a minimal diagnostic baseline

Select 1.

A botanical garden needs one sentence describing each exhibition from three curator-supplied facts. There are no live tools, the facts fit in a short prompt, and a human selects the sentence. A proposed architecture adds fact extraction, planning, drafting and critique agents before any baseline exists. The curator provides an acceptance rubric covering all three facts and tone. Which first experiment BEST tests the simplest viable implementation?

  1. Incorrect. Start with a critic loop limited to one revision, because a bounded loop is the smallest acceptable production architecture.

    A bound controls loop exposure but does not establish that any loop adds value over a sufficient single call.

  2. Correct. Compare one explicitly instructed prompt against the curator rubric, reserving orchestration for demonstrated failure classes that simpler changes cannot fix.

    The task is bounded and supplied with sufficient evidence; measuring the minimal baseline establishes whether orchestration has any necessary purpose.

  3. Incorrect. Collect a training corpus of curator-approved sentences before testing prompts, so stylistic consistency is guaranteed in the first pilot.

    Corpus preparation delays the lowest-cost diagnostic experiment and training data cannot guarantee the required behavior on unseen descriptions.

  4. Incorrect. Implement extraction and drafting agents first, measuring their final output before deciding whether the other proposed agents are necessary.

    This assumes an unnecessary decomposition before measuring whether a single call already satisfies the bounded drafting requirement.

A minimal baseline is an experiment with an explicit acceptance rule. Here the supplied facts, short output and human selection make a single call plausible. Add architectural machinery only when measured failures identify a need and a comparison demonstrates enough improvement to justify its overhead.

Q3 · Feedback must change a tested release

Select 2.

A restoration assistant receives correction notes from conservators. Its dashboard already counts them, but the same unsupported varnish claims recur after every deployment. Privacy-approved excerpts can be retained for evaluation; original production records cannot be reused directly. The team wants a feedback loop rather than an additional runtime filter. Which TWO changes most directly close the loop from observed failure to a verified shared improvement?

  1. Incorrect. Expand retrieval for every request so a greater number of conservation passages accompany the unchanged prompt revision.

    This changes runtime context without establishing why the claim failed or verifying that feedback produced an effective correction.

  2. Incorrect. Send each correction back into the originating conversation and mark the production feedback ticket resolved after acknowledgment.

    Acknowledgment can improve one exchange but does not demonstrate a shared release improvement or prevent recurrence for other conservators.

  3. Incorrect. Add a dashboard showing correction counts by conservator and close the review cycle once the trend becomes visible.

    Visibility supports diagnosis but counting alone does not create a tested behavioral change in the production assistant.

  4. Correct. Turn approved correction excerpts into adjudicated regression cases that preserve the mistaken claim and the required evidence boundary.

    Regression cases convert permitted observations into reproducible criteria that can reveal whether the same failure survives a proposed change.

  5. Correct. Require candidate prompt revisions to pass those cases and a representative holdout before recording and deploying the new version.

    A tested release connects the feedback signal to changed behavior while checking that a narrow repair does not break ordinary work.

A feedback loop needs an evidence-to-change path. Derive permitted regression material, adjudicate the desired behavior, and test a candidate release with broader coverage before deployment. Counting complaints or repairing isolated chats supplies observations but leaves the shared failure mechanism unchanged.

Q4 · Validate extracted usability before expensive work

Select 1.

A geological archive accepts raster maps for an assistant that cites coordinates. A new upload passes the extension and byte-size checks, yet the ingest worker extracts a blank image because the file advertises dimensions inconsistent with its decoded payload. Generation then invents place names. The owner requires readable map evidence or a repairable rejection. Which additional input boundary BEST prevents this failure before model invocation?

  1. Incorrect. Provide a map-reading uncertainty instruction and permit generation whenever the upstream upload returned a successful storage identifier.

    Storage success only establishes persistence and cannot substitute for validation that the model receives readable coordinate evidence.

  2. Incorrect. Run a second model to assess the first generated place names and reject output if the two models disagree.

    Downstream disagreement checking spends inference on unusable input and may still accept mutually plausible invented geography without source evidence.

  3. Correct. Decode with bounded resource limits, verify expected readable content and dimensions, then reject or request repair when the evidence is unusable.

    Checking the actual decoded representation catches the observed mismatch and gives a concrete input failure state before unsupported generation begins.

  4. Incorrect. Lower the accepted file-size limit until every currently failing map is excluded, preserving the existing extension-based validation path.

    A smaller file can contain the same malformed representation; byte size is not proof that usable map content was extracted.

Validate the representation the downstream stage will actually consume. A successful upload is insufficient when decoding can fail or exhaust resources. Bounded decoding and content checks establish a useful input contract, with a clear repair route instead of asking a model to recover missing evidence.

Q7 · Separate critique from persuasive history

    A rejection quota can manufacture apparent scrutiny without improving evidence-sensitive detection of the causal error identified in the scenario.

  2. Correct. Give the critic the draft, rubric and relevant source evidence in a fresh context without the generator’s self-justifying conversation.

  3. Correct. Validate critic discrimination on adjudicated captions with and without subtle causal overstatements before using its verdict as a revision gate.

  5. Incorrect. Hide the source excerpts as well as the author history so the critic’s judgment cannot be influenced by any shared information.

    Independence does not mean withholding task evidence; a critic cannot assess factual support reliably when denied the relevant source material.

Then measure the reviewer on known defects and valid outputs. A higher rejection rate alone is not evidence that criticism has become more accurate.

Q8 · Trace the transformation between specialists

Select 3.

A landscape-history system combines specialist findings into a final chronology. Specialists return source-backed dates, but a synthesis step normalizes ambiguous calendar notation and sometimes introduces the wrong year. Operators can identify the worker source but cannot tell whether the year changed during normalization or final writing. Which THREE trace additions most directly make the introduced claim attributable without requiring unrestricted storage of every underlying document?

  1. Correct. Assign stable claim identifiers and record parent claim links whenever normalization derives a new chronology statement from specialist results.

    A derivation edge identifies which earlier assertion produced the transformed claim, distinguishing worker evidence from a downstream interpretation.

  2. Correct. Attach final chronology statements to their derived claim identifiers and retain controlled source handles under the approved evidence policy.

    Final-to-derived linkage completes attribution across synthesis while controlled handles avoid making every raw historical document an unrestricted trace payload.

  3. Incorrect. Preserve each specialist’s final report and the published chronology, correlating changed dates by nearest matching text at incident time.

    Text similarity can suggest an origin but cannot reliably reconstruct which transformation or assumption introduced a specific changed year.

  4. Correct. Record the normalizer version, explicit calendar assumption and resulting value alongside the input claim identifier for each transformed date.

  5. Incorrect. Record only the specialist name against every published statement, since source-backed worker findings already establish end-to-end provenance.

    Attributing the statement to its worker hides the downstream normalizer that may have introduced the erroneous year during synthesis.

Orchestrator observability must cover transformations as well as worker returns. Record derivation links, transformation versions and relevant assumptions, then connect published statements to those records. This extends the chapter’s worker-provenance lesson to synthesis lineage; it is an application design, not a claim that a platform supplies it automatically.

Q9 · Freeze the shared semantic contract

Select 2.

A cultural catalogue project divides audio annotation by recording. Annotators agree on ordinary instrument names but disagree about whether a historic name means a modern instrument family or a specific object. A curator can approve a disambiguation table. Recordings remain independently processable, and the table may change after review. Which TWO decomposition requirements best prevent internally inconsistent catalogue releases while retaining parallel annotation?

  1. Correct. Run an integration audit for conflicting identifiers and flag batches requiring reprocessing when a material vocabulary revision changes interpretation.

    The audit verifies the shared dependency after parallel work and exposes where updated terminology invalidates earlier annotations rather than hiding inconsistency.

  2. Incorrect. Translate the disputed name into a common language before annotation and treat the translated spelling as the canonical identity.

    Translation can preserve the same ambiguity and does not establish the curator’s domain distinction between an instrument family and an object.

  3. Correct. Bind each annotation batch to a curator-approved vocabulary revision containing the distinctions and evidence rules required by all workers.

When the contract changes, identify affected outputs explicitly; consistency is about stable meaning and evidence, not simply identical surface words.

  2. Incorrect. Expected analyst work falls to 4,800 minutes monthly, an eighty percent reduction, because only escalated cases consume review time.
