Q1 · Instrument the actual bottleneck

Select 1.

An animation studio blames translation for subtitle delays. Editors translate quickly but wait days for terminology approval. Stage timings are unmeasured, and licensor approval cannot change this quarter. What should establish whether AI can meet the delivery goal?

  1. Incorrect. Benchmark translation accuracy and proceed if Claude exceeds the existing editorial quality threshold.

    Translation quality matters later, but a quality benchmark cannot establish that faster translation addresses the dominant delivery delay.

  2. Incorrect. Prototype automatic terminology approval before revisiting the licensor agreement with the business sponsor.

    This changes an explicitly fixed authority boundary, so the prototype cannot validate the proposed intervention under current constraints.

  3. Correct. Measure time by workflow state and compare addressable translation time with the delivery target.

    State-level evidence distinguishes work the proposed system can accelerate from waiting time outside its authority and scope.

  4. Incorrect. Estimate subtitle token costs and prioritize the smallest affordable model for the translation workflow.

    Inference economics optimize a candidate solution without establishing that its addressable interval can materially improve the stated outcome.

Frame the problem around delivery states before choosing a model. If approval waiting dominates and cannot change, even perfect translation acceleration may miss the target. Establish the baseline, addressable time and authority constraints, then decide whether to proceed or redefine scope.

Q2 · Separate prediction from explanation

Select 2.

A heating operator has a validated hourly demand predictor. Dispatchers need explanations using weather notes and maintenance reports. The owner requires numeric forecasts to remain under existing validation. Select TWO recommendations that address the explanation need.

  1. Incorrect. Treat explanations as provisional forecasts and let dispatchers choose the most credible weather-adjusted value.

    This conflates a communication aid with an alternative prediction channel and transfers an unresolved validation problem to dispatchers.

  2. Incorrect. Let Claude correct forecast values when maintenance notes are newer than the predictor’s inputs.

    Recency alone supplies neither validated correction logic nor delegated authority to change the numeric output in this design.

  3. Correct. Test explanation faithfulness and dispatcher comprehension separately from the existing numeric forecast acceptance tests.

    The new capability has its own failure modes; preserving forecast tests alone does not establish useful, supported explanations.

  4. Correct. Keep the predictor authoritative and have Claude explain supplied drivers using linked operational evidence.

    This places language generation around the existing predictor while preserving the owner’s explicitly assigned authority over numeric forecasts.

  5. Incorrect. Replace the predictor with Claude and validate agreement on average totals over one historical month.

    Monthly average agreement can conceal hourly errors and does not satisfy the owner’s requirement to preserve the validated predictor.

The architecture should separate numeric prediction from evidence-based explanation. Preserve the validated service as the authoritative forecast and evaluate the language layer against its actual job: explaining supplied drivers clearly without inventing causes or changing values. This directly addresses the unmet user need.

Q3 · Bind approval to application state

Select 1.

A museum curator approves a collection transfer, but a background process can later change its destination. The asynchronous execution worker checks only approval for the transfer ID. How should it ensure approval covers the destination actually used?

  1. Incorrect. Keep transfer-ID approval and notify the curator when background updates change the destination before execution.

    Notification supplies awareness but does not stop execution under an approval that no longer covers the current destination.

  2. Incorrect. Ask Claude immediately before execution whether the original approval still applies to the transfer summary.

    A semantic similarity judgment cannot enforce that the actual destination and version equal those approved by the curator.

  3. Correct. Bind approval to version and destination; reject execution if either differs from the approved state.

    Version-bound authorization prevents an approval for one destination being reused after the application state changes before execution.

  4. Incorrect. Lock destination editing in the curator interface while permitting background updates to the worker’s destination.

    An interface restriction leaves the identified background mutation path available and therefore fails the stated exact-state requirement.

Approval is an input to execution, not a permanent property of a transfer ID. Check a version or digest that includes the destination at commit time. If relevant state changes, return the case for renewed approval before any instruction is executed.

Q4 · Carry authorized memory forward

A seasonal grant assistant must retain approved project facts between sessions. Users can lose project access, and facts can change. Engineers propose loading a summary by user ID at login. Select TWO necessary additions.

Q6 · Parallel checks need a join rule

Select 1.

A food-labeling platform checks allergens, translation and dimensions on one frozen artwork revision. The checks are independent and all mandatory, but the prototype releases after two pass. Which design meets the requirement without unnecessary sequencing?

  1. Incorrect. Let an orchestrator choose checks, requesting the remainder only when its initial assessment is uncertain.

    The checks are already specified as mandatory, so making their execution discretionary conflicts with the agreed quality policy.

  2. Incorrect. Keep two-of-three release and give the strongest model the check that fails most often.

    Improving one checker does not satisfy the owner’s requirement that all three mandatory checks pass before release occurs.

  3. Correct. Run checks concurrently and release only when all required results pass for the frozen revision.

    Parallel execution is compatible with mandatory checks when the join condition requires every result and binds them to one revision.

  4. Incorrect. Run checks sequentially, release after the second pass and retain the third result for audit.

    Sequential order adds latency while the early release condition still omits a mandatory check from the actual release decision.

Use parallel sectioning for independent checks, coupled with a deterministic all-required join. Bind every result to the frozen artwork revision so late results cannot authorize changed artwork. The architectural issue is the completion condition, rather than whether concurrency itself is appropriate.

Q58 · Migrate a release unit

Select 1.

An aviation assistant’s model is retiring. Its prompt and parser are coupled; the replacement canary uses a new output contract. Rollback restores only the binary, leaving new configuration active. Which lifecycle change makes migration and rollback credible?

  1. Correct. Version model, prompt, schema, parser and routing as a tested unit; validate replacement and rehearse supported rollback.

Select 2.

Q61 · Hooks need failure semantics

Select 1.

A post-edit formatting hook fails on temporarily incomplete generated source. The assistant continues and CI rejects changes. The team wants quick local feedback and formatting assurance. Which design gives the hook a reliable acceptance boundary?

  1. Incorrect. Block edits until future files are formatted, using the post-edit hook to predict whether new source parses.

  2. Incorrect. Replace the hook with detailed project instructions, using guidance to ensure formatting even for temporarily incomplete files.

  3. Incorrect. Count every hook invocation as formatting proof and suppress exit status because intermediate files may be invalid.

Surface local failures, scope the hook appropriately and retain an enforced formatting gate at integration. Q63 · Build an evidence-preserving incident draft

Select 1.

A telescope outage record mixes time zones across alerts, deployments and operator messages. An assistant blames the first deployment mentioned in chat, but engineers have not reproduced the fault. Which method produces a reviewable postmortem while preserving uncertainty?

  1. Incorrect. Adopt the first chat-mentioned deployment as cause and have Claude align the timeline before engineer review.

    Narrative consistency cannot establish causation, and fitting events to the first chat hypothesis risks suppressing evidence that contradicts an initially plausible explanation.

  2. Incorrect. Merge polished source summaries by paragraph length and count repeated claims as independent confirmation of cause.

    Repeated claims can share one original assumption, while paragraph length does not resolve time zones or distinguish independent observations from copied speculation.

  3. Correct. Link normalized timestamps, separate observations from hypotheses and have engineers verify chronology and test causes before publication.

    An evidence-preserving draft accelerates synthesis while retaining temporal provenance and keeping unverified causation separate from facts until the accountable engineers review it.

  4. Incorrect. Publish a preliminary factual postmortem because linked alerts independently verify every causal claim generated from them.

    Source links establish traceability, not automatic causal verification, and publishing speculative conclusions as facts exceeds what the evidence currently supports.

Use the assistant to assemble and normalize evidence, not to promote the first plausible cause into fact. A source-linked timeline with explicit hypotheses gives engineers a useful draft. They must verify timing and test the causal account before owning and publishing the final incident conclusions.
