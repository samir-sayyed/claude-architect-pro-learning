Q1 · Find the queue that actually grows

Select 1.

A museum consortium wants an assistant to answer conservators' status questions. Observation shows that status answers take two minutes, while applications wait nine days because condition descriptions arrive in inconsistent language and must be normalized before scheduling. Scheduling rules are already reliable. The sponsor funds one intervention and will measure days until an application becomes schedulable. Which scope BEST targets that outcome without changing the scheduling authority?

  1. Incorrect. Automate status notifications and report reduced inquiry volume as the first milestone toward shortening application processing time.

    Inquiry volume is a different outcome; fewer questions do not establish that applications become schedulable any sooner.

  2. Correct. Normalize condition descriptions into reviewed fields at intake, then feed those fields into the existing scheduling process, preserving approved scheduling priorities.

    This addresses the observed prerequisite blocking scheduling while leaving reliable rules and the existing decision authority in place.

  3. Incorrect. Deploy a status assistant first and use its conversations to improve condition descriptions during a later project phase, to reduce staff interruptions.

    Status assistance may reduce inquiries, but postpones the constraint responsible for the nine-day wait measured by this sponsor.

  4. Incorrect. Replace the scheduling rules with a planning agent that can infer priorities directly from the unstructured condition descriptions.

    This combines normalization with an unnecessary decision change, increasing scope without evidence that existing scheduling rules cause delay.

The measurement concerns readiness for scheduling, so the architecture must address the input dependency that holds applications upstream. A useful language task can sit inside a stable deterministic process. Scope selection should follow observed delay and retained authority rather than the requested interface.

Q2 · Put language interpretation beside deterministic checks

    The stated pilot preserves existing computation authority; learning through unrestricted actions is unnecessary for measuring note-normalization quality.

  2. Correct. Use Claude to propose normalized inspection notes, with source text visible to staff before those notes are accepted.

    Language normalization is the uncertain activity, and source-visible acceptance supports the pilot's stated accuracy measurement and responsibility.

  3. Correct. Keep registration validation and transport-limit computation in the existing services, exposing their verified results to the assistant.

    These functions already implement approved deterministic rules; their results can support explanation without moving calculation into generation.

Q3 · An uncertain submission needs a durable identity

Select 1.

A scientific instrument portal generates calibration narratives that take several minutes. It accepts a request asynchronously, but a mobile connection sometimes drops before the job identifier reaches the technician. Retrying creates another expensive narrative and another billing entry. The portal already has a worker queue and completion notifications. Which architectural addition BEST resolves the ambiguity at submission while preserving asynchronous processing and legitimate requests for new calibrations?

  1. Correct. Accept a client operation key, persist its job mapping atomically, and return the existing job for repeated submissions.

    A durable submission identity lets the client recover the same accepted operation despite losing the first acknowledgement over the network.

  2. Incorrect. Let the worker finish duplicate narratives, then remove the later result and its bill during nightly reconciliation.

    Reconciliation can correct billing later, but still repeats expensive work and leaves clients uncertain while both jobs are active.

  3. Incorrect. Acknowledge requests before persisting them and rely on completion notifications to tell technicians which submissions actually entered processing.

    An acknowledgement could outlive a lost request; notifications do not repair an acceptance record that was never durably stored.

  4. Incorrect. Deduplicate jobs by instrument identifier and date, allowing only one generated calibration narrative per instrument each calendar day.

    The rule conflates distinct legitimate calibrations; identity must describe the requested operation rather than an overly broad business grouping.

Asynchrony separates acceptance from completion, but also needs an explicit acceptance contract. Bind retries to a stable operation identity and store that identity with the durable job. A repeated transport attempt should recover an operation rather than silently create a second business action.

Q4 · Generated evidence must not become its own authority

Select 2.

A maritime safety assistant retrieves inspection reports and produces maintenance explanations. The team now stores explanations in the same search index to improve coverage. Several explanations cite earlier explanations, although original inspection records disagree. Operations wants to retain useful drafts while preventing unsupported statements from acquiring authority through repetition. Which TWO architecture changes address this failure at the source and context-assembly boundaries?

  1. Incorrect. Rebuild embeddings weekly from the mixed corpus so newer inspection reports and earlier explanations receive comparable retrieval treatment.

    Re-embedding changes representation without separating authority; the same circular source relationships survive each rebuild and remain available for reuse.

  2. Correct. Store generated explanations separately with explicit provenance, and exclude unreviewed drafts from the authoritative evidence retrieval path.

    Separating generated material prevents circular retrieval from silently elevating an unverified explanation into an authoritative inspection fact.

  3. Incorrect. Keep one index and favor documents cited most often, because repeated citations identify statements that previous answers found useful.

    Citation frequency in a feedback loop measures repetition, not independent evidence, and can amplify precisely the unsupported statements observed.

  4. Correct. Assemble answers from versioned inspection evidence and require reviewed promotions to identify the original records supporting each claim.

    Versioned originals and accountable promotion preserve a traceable chain instead of treating repeated generated wording as independent corroboration.

  5. Incorrect. Retain generated explanations as evidence but attach a general disclaimer to every answer that references the mixed search index.

    Disclosure does not restore original support or prevent generated errors from being reused as the basis for subsequent answers.

The failure arises from the provenance of retrieved material rather than a lack of fluent generation. Generated drafts can remain useful artifacts, but their evidentiary status must be explicit. Promotion into an authoritative collection requires review tied to the original observations that support the promoted statements.

Q6 · A quality gate needs a failure transition

Select 1.

A multilingual training publisher generates a lesson outline, checks learning-objective coverage, then commissions audio narration. Coverage checking is accurate, but failed outlines still trigger expensive narration because the check returns prose that the orchestrator only logs. The publisher wants one repair attempt before a case moves to an editor. Which design BEST changes the workflow so the quality check actually controls downstream work?

  1. Incorrect. Send every failed outline to an editor immediately and allow narration to proceed while the editor reviews it asynchronously.

    The editor may detect the issue, but narration still starts from an outline that has not passed the stated prerequisite.

  2. Incorrect. Increase the coverage checker's effort and log a numerical confidence score before commissioning narration for every completed outline.

    A more confident check still has no failure transition; work continues regardless of whether the outline meets the required coverage.

  3. Incorrect. Add the coverage report to the narration prompt and require the narrator to repair missing objectives while producing the audio script, before any independent editor review.

    This bypasses the agreed outline gate and combines repair with expensive downstream work before coverage has been established as acceptable.

  4. Correct. Return a validated coverage decision and missing-objective list; branch to one repair attempt, then hold unresolved outlines for editing, before commissioning any narration.

    A machine-readable verdict drives an enforceable transition, and a bounded repair path uses the missing-objective evidence before escalation.

A gate is an orchestration decision, not simply an additional model response. Define the verdict schema, permitted repair count, and safe terminal state. Only the accepted branch should unlock narration, so failed checks cannot be acknowledged in logs while remaining operationally irrelevant.

Q7 · Recovery must preserve completed effects

Select 2.

An environmental audit run assigns laboratories to workers, then creates signed evidence bundles. After a coordinator restart, completed laboratory analyses are rerun and some signed bundles are issued twice. Analysis results are already persisted, but the coordinator stores only a free-text progress summary. Which TWO changes most directly support correct recovery while retaining parallel laboratory work and the existing bundle-signing service?

  1. Incorrect. Let each laboratory sign its bundle independently and merge their reports only after every worker has finished its own retries.

    Distributed signing without shared operation identities preserves the same duplicate-effect ambiguity and makes overall recovery harder to coordinate and audit.

  2. Correct. Persist structured task states with input versions and completion identifiers, restoring only unfinished tasks after a coordinator restart.

    A recoverable task graph distinguishes completed analyses from outstanding work and makes resume decisions independent of ambiguous narrative summaries.

  3. Incorrect. Checkpoint the coordinator's entire conversation after each laboratory response and replay every signing tool call when the conversation is restored.

    Replaying side effects can duplicate already issued bundles; a conversation checkpoint does not establish whether an external submission already committed.

  4. Correct. Give each bundle operation a stable identity and reconcile its recorded signing outcome before retrying an uncertain external submission.

    Persisted task state alone cannot prevent duplicate external effects when a crash occurs between the signing service and coordinator acknowledgement.

  5. Incorrect. Restart failed runs from the oldest completed laboratory and use newly generated timestamps to distinguish replacement bundles from earlier ones.

    New timestamps create distinct operations rather than recognize retries, so completed analyses and externally visible bundle effects are unnecessarily repeated.

Recovery spans two kinds of state: completed computation and committed external effects. Preserve structured task progress, and make effect retries refer to the same operation identity. A resumed coordinator should continue the remaining work while reconciling ambiguous submissions instead of treating every recovered tool call as new.

  3. Incorrect. Disable compaction and paste all earlier terminal output into every new turn, preserving every byte as the only reliable way to avoid repeated experiments.

    Unbounded history refills the context and adds noise; useful continuity depends on durable findings and retrievable evidence rather than endlessly replaying every intermediate output.

  4. Incorrect. Write the currently favored hypothesis into project instructions as the established root cause, so future sessions no longer spend context reconsidering it.

    The cause remains unresolved; turning a hypothesis into standing truth contaminates future diagnosis and can suppress the evidence needed to discover the actual fault.

A debugging conversation is temporary working memory. Persist the evidence that constrains the next experiment: reproducible environment, tested hypotheses, observed outcomes, and open questions. Reload supporting details when needed. This preserves continuity across compaction while keeping unverified explanations separate from findings the investigation has actually established.
