Q1 · Place the language boundary

Select 1.

A seed laboratory has a validated formula for certified germination percentages. Scientists need faster explanatory notes; a pilot extracts relevant narrative observations with source links. Certification must remain reproducible, and only one integration is funded this quarter. Which architecture fits?

  1. Correct. Draft linked observation notes alongside formula results, keeping certified calculations in the validated laboratory service.

    This uses demonstrated language capability without changing the reproducible calculation that already satisfies the laboratory requirement.

  2. Incorrect. Have Claude calculate percentages and explanations together, comparing only its prose against existing scientist notes.

    The comparison would leave the changed numerical calculation unvalidated, despite reproducibility being an explicit release constraint here.

  3. Incorrect. Use an autonomous agent to choose formulas from observations and submit completed certificates for the laboratory.

    Formula selection and certificate submission introduce new authority beyond the demonstrated benefit and the stated integration scope.

  4. Incorrect. Generate all explanations with numerical templates before evaluating the pilot’s ability to extract narrative observations.

    Templates may help, but this discards demonstrated language value without testing whether fixed text covers the field observations.

Use the demonstrated language capability where it helps scientists interpret observations, while preserving the validated numerical calculation. The useful boundary lies between preparing an explanation and computing a certified quantity; combining both under model control adds risk without addressing an unmet need.

Preferred components and impressive demonstrations cannot substitute for a service definition the owners will evaluate.

Q3 · Repair only the presentation

Select 1.

A museum kiosk may display only text and validated catalogue IDs; HTML and external links are prohibited. Accurate drafts sometimes contain Markdown links. Which design enforces the contract before delivery while preserving useful draft content?

  1. Correct. Parse constrained responses, validate catalogue IDs and render escaped text with the existing kiosk component.

    The delivery boundary can enforce the actual interface contract independently of whether the model follows the formatting instruction.

  2. Incorrect. Put the display rules in the system prompt and render returned Markdown in a general browser component.

    This still accepts unvalidated presentation syntax and changes the renderer rather than enforcing the kiosk’s permitted output contract.

  3. Incorrect. Reject visitor questions containing URLs, then pass model responses through because unsafe syntax was removed upstream.

    Input filtering does not constrain syntax newly generated in an answer, so it leaves the identified output failure unresolved.

    The feedback loop can improve generation but cannot prevent contract violations in answers already delivered to the public kiosk.

The presentation contract belongs in a deterministic boundary before rendering. Structured parsing and allowlisted identifiers can reject invalid payloads and permit bounded repair without discarding the factual generation step. A prompt helps formation but is not the enforcement mechanism for the display interface.

Q4 · Fresh facts with a failure state

A ferry assistant must use sailing data under two minutes old for current departure claims. During live-service failures, variably aged cached data may appear only as historical. Select TWO behaviors that preserve this contract.

This is distinct from fixed sectioning because the actual subtasks emerge from the input. Isolation, result contracts, and a final consistency check remain necessary even when discovery is dynamic.

Q7 · A partial worker result is evidence

Select 1.

A survey delegates seismic, water-table and land-use research. The report must link recommendations to observations. Water-table research covers two of four zones, timing out on the rest; one retry fits the deadline. Which design preserves valid partial work?

  1. Incorrect. Accept any nonempty response and let the orchestrator infer missing zones from measurements in neighboring areas.

    Nonempty output does not demonstrate complete coverage, and inference would conceal the missing evidence required for zone-specific recommendations.

  2. Incorrect. Discard all specialists’ findings and rerun the whole survey whenever a worker returns fewer measurements than requested.

    Whole-job retries waste successful evidence and still lack a result contract that distinguishes missing coverage from completed observations.

  3. Correct. Return covered zones, sources and partial status; retry missing zones within budget and disclose remaining gaps.

    The contract preserves successful evidence and makes missing coverage visible while respecting the deadline and the allowed retry budget.

  4. Incorrect. Have the seismic specialist rewrite water-table findings from its own context so the report remains complete.

    A different worker’s contextual knowledge does not replace the missing measurements or preserve their provenance in a zone-specific report.

Worker results should carry scope and explicit completion status. The orchestrator can reuse successful zones, bound the retry, and preserve unresolved gaps in the final analysis. It should not collapse a partial investigation into either invented completeness or the loss of all otherwise useful evidence.

Q8 · Keep a shared budget enforceable

Select 3.

Film-restoration specialists investigate frames, sound and historical references. The orchestrator currently launches workers for every suggested lead. Each reel has a strict budget; disclosed unfinished research is acceptable. Select THREE controls supporting flexible but bounded investigation.

  1. Correct. Rank new leads by expected value and stop expansion when remaining reserved funds cannot cover them.

    Prioritization preserves flexibility within the enforceable limit instead of allowing recursively proposed work to expand the job without bounds.

  2. Incorrect. Increase every specialist’s output cap to reduce the number of messages in the final activity report.

    Message count is not a reliable spending boundary and longer outputs can increase cost without controlling worker or tool fanout.

  3. Correct. Reserve worker and tool-call allowances against one job budget, counting concurrent work already in flight.

    Atomic shared accounting prevents simultaneously launched workers from each spending what appears to be the same remaining budget.

  4. Correct. Give workers termination conditions and require structured findings with unresolved leads when assigned allowances run out.

    Local bounds prevent an individual investigation from continuing indefinitely and preserve useful evidence when its allotted effort is insufficient.

  5. Incorrect. Calculate costs after all specialists finish, then delete low-value sections until the published report fits budget.

    Editing the report cannot recover resources already consumed, so retrospective accounting does not enforce the processing budget during investigation.

Flexible delegation requires enforceable resource accounting and explicit partial outcomes. Reserve a shared budget before work starts, bound workers locally, and stop expansion when the job cannot fund it. A useful result can document unresolved leads; hiding or postponing accounting cannot make an open-ended investigation bounded.

  5. Correct. Version schemas and deployment dependencies, linking acceptance checks and rollback guidance to the handed-over configuration.

    Versioned dependencies and checks help receiving teams deploy compatible components and recover a change without relying on the original architect’s memory.

Document the control at its actual data boundary, the interface behavior on failure, and the versioned operational dependencies. These details turn a component picture into an actionable handoff contract. A meeting or a code reference alone cannot ensure that three teams share the same responsibilities and failure expectations after personnel change.

Q58 · Accept the handoff in practice

Select 1.

A coastal assistant passes evaluations before museum handoff. Runbooks exist, but receiving staff have never restored service, acknowledged alerts or rolled back configuration. Public exhibition staffing will be limited. Which action establishes readiness before responsibility transfers?

    Reading establishes awareness but does not test actual permissions, procedures, or infrastructure behavior needed to perform restoration and rollback.

  2. Incorrect. Transfer immediately because passing model evaluations establishes that infrastructure incidents and rollback will not occur during exhibitions.

    Model quality gates do not validate the receiving team’s operational access or ability to recover infrastructure and configuration failures.

  3. Incorrect. Route alerts to the original architect until a first museum incident provides operational training under pressure.

    The original architect remains a fragile dependency, and learning during a public incident does not establish readiness before the responsibility transfer.

  4. Correct. Have museum and builders rehearse alerts, access, restoration and rollback together; close gaps before formal acceptance.

    The receiving team demonstrates the actual responsibilities it will own, testing both the documentation and the configured operational paths before the exhibition.

Exercise the operating responsibilities with the team that will own them and use the results as handoff evidence. Written runbooks are necessary but do not establish that access, alerts, restoration, and rollback work in practice. Q59 · Expand on observed operating evidence

Select 1.

A citizen-history proof of concept passes on curated records. A live pilot reveals unusual formats and catalogue timeouts recoverable through existing human routes. The sponsor wants nationwide release. Which proposal expands value while learning from these operating conditions?

  1. Incorrect. Defer all expansion until catalogues guarantee no future timeouts, regardless of recovery evidence and accepted service goals.

    An absolute external guarantee is not the stated acceptance requirement; controlled expansion can evaluate bounded recovery instead of demanding impossible certainty.

  2. Incorrect. Release nationwide because recoverable pilot failures establish that human routes automatically scale across regions and formats.

    The existence of a recovery route does not establish its nationwide capacity or effectiveness across the newly expanded operating population.

  3. Correct. Expand in bounded waves after testing formats, timeout recovery, owner response and rollback against pilot-derived gates.

    The staged plan targets the actual operating uncertainty and allows broader value when measured evidence supports the next population increase.

  4. Incorrect. Repeat curated demonstrations for higher scores, treating improvement as evidence that live catalogue timeouts are resolved.

    The curated dataset does not exercise the new operational failure classes, so a higher score would not answer the rollout-readiness question.

Use staged expansion with observable gates tied to the failure classes discovered in live operation. Exercise recovery and rollback, then widen the population when the evidence supports it. A successful curated proof of concept does not measure nationwide operational diversity, while repeating it unchanged would not address the new uncertainty.

Q60 · Policy inheritance is not a local exception

Select 1.

An institute centrally denies a Claude Code tool. A project adds a narrower allow rule, assuming specificity overrides denial, but administrators intend the central restriction to remain binding. Which response respects precedence while addressing the legitimate workflow need?

  1. Incorrect. Move the allow rule into project instructions because instructions follow managed settings and therefore take precedence.

    Instruction text does not change the enforced permission policy, and moving the request there cannot legitimately override the central denial.

  2. Correct. Confirm and enforce the managed denial; ask its owner to review a scoped replacement or policy change.

    The approach respects deny precedence while making the workflow need concrete for the authority that can legitimately alter the managed boundary.

  3. Incorrect. Disable managed settings for this repository because a valid research purpose permits independent project tool policy.

    The project’s legitimate need does not authorize removing institute controls; the intended exception process belongs to the managed-policy owner.

  4. Incorrect. Keep the narrower allow because specific argument patterns always override broader managed denials for the same tool.

Q61 · Independent checks for a generated change

Select 2.

A sediment parser treats missing readings as zero, contrary to agreed requirements. Generated tests copied that behavior and pass. Select TWO workflow changes establishing intended semantics independently of the mistaken implementation.

  1. Incorrect. Generate additional expected outputs from the current parser, treating a larger passing suite as intended-semantic evidence.

    A larger suite can reinforce the same incorrect oracle and does not establish the requirement that missing readings remain distinct from zero.

  2. Incorrect. Approve increased coverage without checking fixture expectations against the agreed treatment of missing readings.

    Coverage shows execution, not correctness of the expected behavior, and cannot resolve whether the tests encode missing values or incorrect zeroes.

  3. Correct. Review the diff in fresh context against the contract; run downstream calculations distinguishing missing from measured zero.

    Independent review and integration checks test the semantic consequence that a generated unit suite mirroring the old behavior failed to expose.

  4. Correct. Create requirement-derived missing-value fixtures and confirm failure on old behavior before accepting implementation changes.

    The failing fixtures establish an independent behavioral oracle for missing readings rather than copying the current implementation’s incorrect zero substitution.

  5. Incorrect. Let the authoring session rewrite expected values until all tests pass, treating code consistency as truth.

    Rewriting expectations to match implementation removes the independent behavioral check and can preserve the exact missing-value defect the team must correct.

Establish expected behavior from the requirement before accepting generated tests, then review the change with independent context and run the relevant integration checks. Test-first work is useful when its oracle is independently grounded. More assertions or self-review cannot compensate for tests that encode the wrong missing-value contract.

Q62 · Find the event before proposing the fix

Select 1.

A photogrammetry build fails intermittently after worker rescheduling. Multi-gigabyte logs include unrelated credentials, and Claude Code has restricted local search. Which diagnostic approach retains evidence distinguishing races from environment mismatches while reducing context and secret exposure?

  1. Correct. Search the failed job and time window, redact secrets, compare schedules and reproduce the leading hypothesis.

    The approach preserves causal evidence while limiting context and exposure, and it produces a testable explanation before changing the intermittent build behavior.

  2. Incorrect. Add two retries and close after a successful rescheduled run, treating that success as proof of cause.

    A successful retry shows the symptom is intermittent but does not distinguish a race from an environment mismatch or establish that either was fixed.

  3. Incorrect. Delete failing logs after saving the error so reproduction begins with cleaner context and less historical confusion.

    The surrounding schedule and environment events may be necessary to explain the failure; deleting them removes evidence rather than narrowing it safely.

  4. Incorrect. Upload all logs unchanged, relying on complete context to distinguish race conditions from environment mismatches for repair.

    Unfiltered volume does not guarantee useful reasoning and unnecessarily exposes credentials without first narrowing the causal evidence relevant to the failing job.

Start with bounded, redacted evidence around the failed job and compare it with a successful counterpart. Build a reproducible hypothesis from correlated events before proposing a repair. Tool-assisted narrowing is useful because large raw logs contain irrelevant and sensitive material; retries alone can conceal the cause without explaining it.

Q63 · Contain a credential exposure

Select 1.

During outage diagnosis, an engineer pastes an active token that reads restricted source documents into an assistant session. The incident owner may rotate it and preserve audit evidence. Which response addresses exposure and improves subsequent investigation?

  1. Correct. Rotate the token, review relevant access under incident procedures and continue with redacted configuration and restricted tools.

    Rotation contains future credential use, while the audit and safer diagnostic path address the exposure and reduce recurrence without destroying necessary evidence.

  2. Incorrect. Delete the message and retain the token because removing visible text revokes access across all processing systems.

    Message deletion does not revoke a credential or prove removal of all copies, so its live authority remains a material unresolved exposure.

  3. Incorrect. Base64-encode the same token before resharing because encoding prevents the assistant and downstream readers recovering it.

    Base64 is reversible encoding rather than secret protection, and sharing the encoded live token preserves the same underlying credential-exposure risk.

  4. Incorrect. Ask Claude to forget the token and rename the configuration file, retaining credentials to avoid disrupting diagnosis.

    A model instruction does not invalidate the credential or establish that other retained copies cannot be used while the investigation continues.

Invalidate the exposed credential, investigate its use under the incident procedure, and repair the evidence-sharing path with redaction and access boundaries. Rotation changes the credential’s future authority; deleting visible text does not prove all copies disappeared. Preserve audit evidence according to the incident owner’s scope rather than destroying it as a cleanup shortcut.
