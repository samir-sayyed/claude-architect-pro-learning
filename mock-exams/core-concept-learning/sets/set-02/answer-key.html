Q1 · Place the language boundary

Select 1.

A seed laboratory receives narrative field observations and numerical germination counts. Scientists already use a validated formula to calculate the certified germination percentage. They want faster preparation of explanatory notes, but the certificate calculation must remain reproducible. A pilot can identify relevant observations with source links. The release budget permits one integration this quarter. Which initial architecture BEST fits the evidence?

  1. Correct. Draft source-linked observation notes beside the existing formula result, leaving certification calculations in the validated laboratory service.

    This uses demonstrated language capability without changing the reproducible calculation that already satisfies the laboratory requirement.

  2. Incorrect. Have Claude compute percentages and explanations together, then compare only the prose against the scientists’ existing notes.

    The comparison would leave the changed numerical calculation unvalidated, despite reproducibility being an explicit release constraint here.

  3. Incorrect. Build an autonomous research agent that chooses formulas from the observation text and submits completed laboratory certificates.

    Formula selection and certificate submission introduce new authority beyond the demonstrated benefit and the stated integration scope.

  4. Incorrect. Use the existing numerical formula to generate every explanation through templates before evaluating the narrative extraction pilot.

    Templates may help, but this discards demonstrated language value without testing whether fixed text covers the field observations.

Use the demonstrated language capability where it helps scientists interpret observations, while preserving the validated numerical calculation. The useful boundary lies between preparing an explanation and computing a certified quantity; combining both under model control adds risk without addressing an unmet need.

Q2 · A measurable launch envelope

Select 2.

A festival accessibility team wants a multilingual information assistant before ticket sales open. The sponsor asks the architect to choose a model now, although no one has agreed what acceptable service means. Staff can review sample answers, and venue policies are available. Which TWO findings should be established as requirements before choosing the model and orchestration pattern?

  1. Incorrect. Require exactly three specialist agents because the event supports three languages and each language deserves isolated reasoning.

    The number of languages alone does not establish an orchestration need or measurable quality, latency, and capacity expectations.

  2. Correct. Agree how quickly venue changes must appear in answers and who supplies authoritative updates during the event.

    Freshness and source ownership constrain the data path and operational responsibilities rather than presupposing a particular technical design.

  3. Correct. Agree supported languages, peak concurrent demand, and the maximum user-visible response time at the ticket-sale launch.

    These define observable service expectations that affect model selection, load planning, and evaluation before implementation choices are locked.

  4. Incorrect. Use the sponsor’s favorite demonstration as the launch baseline without measuring staff work or expected attendee demand.

    A demonstration provides examples but cannot establish the current baseline or the volume and constraints of the real service.

  5. Incorrect. Choose a vector database first and treat its default retrieval settings as the assistant’s acceptance criteria.

    A component default describes implementation behavior; it does not establish the service outcome festival users and operators require.

Requirements must constrain an architectural choice in observable terms. Language coverage and a demand envelope drive quality and capacity testing; an accepted freshness rule constrains integration. Preferred components and impressive demonstrations cannot substitute for a service definition the owners will evaluate.

Q3 · Repair only the presentation

Select 1.

A museum kiosk explains objects using retrieved catalogue records. A public-display contract permits only text and a validated catalogue identifier; HTML and external links cannot reach the screen. Curators confirm that the factual drafts are accurate, but some outputs contain Markdown links. The team wants to keep useful drafts while enforcing the display contract before delivery. Which design BEST establishes that boundary?

  1. Correct. Parse a constrained response, validate catalogue identifiers, and render escaped text through the kiosk’s existing display component.

    The delivery boundary can enforce the actual interface contract independently of whether the model follows the formatting instruction.

  2. Incorrect. Put the display contract in the system prompt and render the returned Markdown through a general-purpose browser component.

    This still accepts unvalidated presentation syntax and changes the renderer rather than enforcing the kiosk’s permitted output contract.

  3. Incorrect. Reject every visitor question containing a URL, then allow the model response through because unsafe syntax was removed upstream.

    Input filtering does not constrain syntax newly generated in an answer, so it leaves the identified output failure unresolved.

  4. Incorrect. Log presentation violations for curator review after displaying the answer, and tune examples during the next monthly release.

    The feedback loop can improve generation but cannot prevent contract violations in answers already delivered to the public kiosk.

The presentation contract belongs in a deterministic boundary before rendering. Structured parsing and allowlisted identifiers can reject invalid payloads and permit bounded repair without discarding the factual generation step. A prompt helps formation but is not the enforcement mechanism for the display interface.

Q4 · Fresh facts with a failure state

Select 2.

A ferry operator’s assistant explains boarding options from the live sailing service. When that service fails, an old cache is available but its age varies. The operator requires that current departure claims use data under two minutes old; older information may be shown only as historical. Which TWO architectural behaviors preserve this contract during intermittent source failures?

  1. Incorrect. Allow the model to promote cached times to current times whenever previous schedules have usually remained unchanged.

    Historical stability does not establish current source freshness and therefore cannot satisfy the explicitly stated departure-information contract.

  2. Incorrect. Strip cache timestamps before context assembly so the assistant uses the most relevant departure regardless of retrieval age.

    Removing timestamps eliminates the evidence needed to distinguish permitted historical information from a prohibited current departure claim.

  3. Correct. Return a clear unavailable state with the permitted historical view and the operator’s live-information contact route.

    This preserves useful degraded service while distinguishing historical evidence from a current departure claim the system cannot support.

  4. Incorrect. Retry the live service without a deadline while keeping the visitor’s request open until a fresh answer appears.

    Unbounded waiting does not provide a controlled failure state and can consume service capacity during a prolonged source outage.

  5. Correct. Attach retrieval time and source status to sailing results, and validate freshness before stating a current departure.

    The architecture needs observable evidence age to enforce the operator’s two-minute requirement rather than infer freshness from fluent wording.

Freshness must travel with the evidence, and delivery must enforce its meaning. A stale result can retain historical value without supporting a current departure claim. An explicit source failure lets the application provide a useful alternative rather than silently manufacturing freshness or concealing degraded operation.

Q5 · Discover tasks before assigning them

Select 1.

An archaeology archive is migrating inconsistent collection descriptions into a new taxonomy. Some collections need only terminology changes; others reveal missing relationships that require additional investigation. A fixed initial survey can identify which collections need which follow-up work, but the follow-ups cannot all be enumerated beforehand. Each worker can operate on an isolated collection snapshot. Which pattern BEST fits this variable decomposition?

  1. Incorrect. Route every collection to one of two predefined rewrite prompts and prohibit additional investigation when a relationship is missing.

    The predefined routes cannot cover the newly discovered investigations that the scenario explicitly requires for some collection records.

  2. Correct. Use an orchestrator to inspect the survey, assign bounded collection investigations, and reconcile their outputs against the new taxonomy.

    Dynamic task discovery matches the variable follow-ups, while bounded worker assignments and synthesis preserve an understandable migration process.

  3. Incorrect. Create one fixed parallel worker per taxonomy term and let each independently rewrite every collection that mentions its term.

    Term-based fanout duplicates edits across collections and does not match the collection-specific work discovered by the initial survey.

  4. Incorrect. Use a critic loop on the complete archive until the critic declares that every description has become internally consistent.

    An archive-wide critic does not define bounded discovered tasks and lacks a clear method to resolve collection-level dependencies.

An orchestrator can discover the required work from the survey and assign bounded collection tasks, then integrate results. This is distinct from fixed sectioning because the actual subtasks emerge from the input. Isolation, result contracts, and a final consistency check remain necessary even when discovery is dynamic.

Q6 · A critic needs a measurable purpose

Select 2.

A public radio team generates brief programme descriptions. It has a precise prohibited-claims list and a rubric for whether the description faithfully reflects a recording. Independent editors can explain which failures a revision fixes. The team is considering a bounded evaluator loop instead of five independent drafts. Which TWO pieces of evidence most strongly support choosing the evaluator loop?

  1. Incorrect. The evaluator writes longer explanations than human editors, demonstrating that it has inspected more evidence than the generator.

    Explanation length is not evidence of accurate judgment or useful feedback and can hide verbosity bias in evaluation.

  2. Incorrect. The new loop uses the same prompt and context as the generator, ensuring that no independent interpretation can disagree.

    Sharing assumptions can reinforce the initial error; agreement alone does not validate the critic’s judgment or the revised description.

  3. Incorrect. Five drafts frequently repeat the same mistake, so any critic model must necessarily produce a correct alternative description.

    Correlated generation errors do not establish critic competence; the critic itself needs measurement against the known failure cases.

  4. Correct. Editors can calibrate the evaluator on faithful and misleading descriptions using the same explicit claims and fidelity rubric.

    A calibrated, actionable evaluation signal gives the revision process a defensible target and makes failures of the critic observable.

  5. Correct. On held-out recordings, rubric-specific feedback produces better revised descriptions than the initial drafts within the allowed response time.

    This demonstrates useful refinement under the product constraint rather than assuming that additional model calls necessarily improve the result.

The evaluator-optimizer pattern is supported by actionable criteria and demonstrated improvement through feedback. It is not justified simply because another model can comment. Compare the bounded loop with simpler alternatives under the same rubric, and include the extra cost and elapsed time in the decision.

Q7 · A partial worker result is evidence

Select 1.

A geological survey assistant delegates seismic, water-table, and land-use investigations. Its report must identify which observations support each recommendation. The water-table worker returns usable measurements for two of four zones and times out on the others. Retrying is allowed once within the report deadline. Which orchestration design BEST uses the successful work without implying coverage the system does not have?

  1. Incorrect. Treat any nonempty worker output as success, allowing the orchestrator to infer unreported zones from neighboring measurements.

    Nonempty output does not demonstrate complete coverage, and inference would conceal the missing evidence required for zone-specific recommendations.

  2. Incorrect. Discard all workers’ findings and rerun the entire survey whenever any worker returns fewer measurements than originally requested.

    Whole-job retries waste successful evidence and still lack a result contract that distinguishes missing coverage from completed observations.

  3. Correct. Return covered zones, sources, and partial status; retry missing zones within budget and mark unresolved coverage in the report.

    The contract preserves successful evidence and makes missing coverage visible while respecting the deadline and the allowed retry budget.

  4. Incorrect. Have the seismic worker rewrite the water-table section using its own contextual knowledge so the final report remains complete.

    A different worker’s contextual knowledge does not replace the missing measurements or preserve their provenance in a zone-specific report.

Worker results should carry scope and explicit completion status. The orchestrator can reuse successful zones, bound the retry, and preserve unresolved gaps in the final analysis. It should not collapse a partial investigation into either invented completeness or the loss of all otherwise useful evidence.

Q8 · Keep a shared budget enforceable

Select 3.

A film restoration service uses specialists to investigate damaged frames, soundtrack defects, and historical references. Costs vary widely across reels. An orchestrator currently starts more workers when any worker suggests another lead. A reel has a strict processing budget, and unfinished investigation is acceptable if disclosed. Which THREE controls together support flexible investigation while reliably bounding the service’s exposure?

  1. Correct. Have the orchestrator rank new leads by expected value and stop expansion when the remaining reserved budget cannot fund them.

    Prioritization preserves flexibility within the enforceable limit instead of allowing recursively proposed work to expand the job without bounds.

  2. Incorrect. Raise the model’s maximum output length for every specialist so fewer messages appear in the job’s final activity report.

    Message count is not a reliable spending boundary and longer outputs can increase cost without controlling worker or tool fanout.

  3. Correct. Reserve worker and tool-call allowances against one job-level budget before dispatch, including concurrent work already in flight.

    Atomic shared accounting prevents simultaneously launched workers from each spending what appears to be the same remaining budget.

  4. Correct. Give workers explicit termination conditions and require structured findings with unresolved leads when their assigned allowance is exhausted.

    Local bounds prevent an individual investigation from continuing indefinitely and preserve useful evidence when its allotted effort is insufficient.

  5. Incorrect. Calculate total cost only after every specialist finishes, then remove low-value sections until the published report fits the budget.

    Editing the report cannot recover resources already consumed, so retrospective accounting does not enforce the processing budget during investigation.

Flexible delegation requires enforceable resource accounting and explicit partial outcomes. Reserve a shared budget before work starts, bound workers locally, and stop expansion when the job cannot fund it. A useful result can document unresolved leads; hiding or postponing accounting cannot make an open-ended investigation bounded.

Q11 · Degraded service has a contract

Select 2.

A library research service wants resilience when its preferred model is unavailable. A candidate fallback meets citation-format checks but performs worse on complex cross-document contradictions. Librarians permit fallback for catalogue summaries, while disputed historical claims must wait for the primary route or a librarian. Which TWO design decisions make the availability improvement consistent with the accepted quality trade-off?

  1. Incorrect. Keep fallback use invisible to operators and users because a successful API response demonstrates that the availability objective was met.

    API success can conceal unacceptable task outcomes and prevents operators from observing the degraded behavior whose risk was explicitly accepted.

  2. Incorrect. Expand the fallback’s context automatically until it matches the primary model’s quality, without rerunning the research acceptance evaluations.

    More context is an untested hypothesis, not evidence that the fallback now satisfies the complex-task quality requirement.

  3. Correct. Classify permitted fallback task classes and evaluate the fallback against their own acceptance criteria before enabling automatic substitution.

Route only validated classes to the fallback, and expose degraded handling where the quality-sensitive class cannot be served. Availability measurements should count permitted outcomes rather than treating every HTTP success as an acceptable research answer.

Q55 · Define the thing users experience

    Combining different events conceals the failure mode and does not establish a defensible service target for either responsiveness or usable completion.
