## Verification and corrections

The references below were actually opened during this authoring session, not inferred from search snippets. Current product pages were checked on 2026-10-18. Questions cite the relevant subset in the source registry.

- Anthropic’s agent architecture article supports composable workflows, dynamic decomposition, bounded agent loops, and evidence-based increases in complexity. The article itself warns that its 2024 tooling details have changed. Pattern advice is not a claim that every new SDK behaves identically.
- Prompting documentation supports clear sections, diverse examples, explicit audience and output requirements. XML delimiters improve interpretation; they are not authorization boundaries. Examples were not treated as a hard guarantee against injection.
- Prompt caching documentation confirms stable prefix reuse and distinct cache read/write usage. Longer TTL cannot make unequal prefixes match. No source model prices were copied into the scored questions.
- Token-counting documentation accepts system text, local tools, and embedded multimodal content, but excludes some server-tool/MCP and URL/file-source inputs. Q16 therefore specifies a base64-embedded image and a supported actual request. Counting remains an estimate; admission retains headroom. The source video’s simplified “exact request” wording is not treated as an absolute guarantee.
- Skills documentation distinguishes metadata, triggered instructions, and referenced resources. Q19 applies this loading model without promising that skill installation is costless or that every platform has identical controls.
- MCP authorization was checked against the opened 2026-07-28 text: resource indicators belong in authorization and token requests, and resource servers validate audience. Local stdio is a distinct transport case; downstream APIs can still require credentials.
- The opened dated MCP security guidance covers private destinations, redirects, DNS resolution, and independent egress controls. Q42 corrects the oversimplified notion that a hostname list alone necessarily prevents every internal-network fetch.
- Claude Code permissions explicitly resolve deny before ask before allow; specificity does not create a local exception to managed denial. Sandboxing documentation supplies the filesystem-isolation layer. Q43 corrects the source’s broad hook-only enforcement implication: a lexical path hook can miss symlinks and alternate shell writes.
- Anthropic evaluation guidance favors scalable grading where appropriate but recognizes nuance. The companion does not generalize “more automated cases” into “automation always replaces expert calibration.” Q35 combines deterministic checks, calibrated judges, and expert challenge cases.
- Hallucination guidance supports source verification and uncertainty. Q39 treats disagreement as a triage signal; neither majority agreement nor a minority claim establishes truth by itself.
- Google SRE and OpenTelemetry support user-visible symptoms, useful tail measurements, causal context propagation, and actionable operational ownership. Numerical queue and budget examples are explicitly fictional, with independent calculations below.
- GDPR Article 5(1)(c) and 5(1)(e), with Article 4(5)/Recital 26 context, support necessity, storage limitation, and the distinction between pseudonymous and anonymous information. Q48 and Q49 stipulate applicability and counsel/controller decisions. Ninety days is a scenario-specific approved period, not a legal universal. No claim is made that encryption alone establishes minimization or that primary-store deletion covers every derivative.
- NIST AI RMF 1.0 supports context-sensitive risk, measured human-AI configurations, explainability/transparency, affected stakeholders, and bias management. It does not prescribe the fictional organizations’ risk tolerances. Review, fairness, and handoff cases are architectural applications rather than assertions that a framework checklist guarantees safety.

Unstable source claims about named model generations, shared context/output limits, token prices, model retention exceptions, product-specific HIPAA coverage, or platform-specific eligibility were deliberately not turned into rote scored facts. They require current contractual and product-specific review. The form’s hard judgments instead use stipulated requirements and measured alternatives.

## Originality and difficulty limits

A concept digest was prepared from all three complete videos before writing. The 63 items use new task mechanisms, data, constraints, option wording, distractors, and rationales. They are not a synonym substitution or a transcript transcription. No existing exam-bank questions were used as content; the existing data file was inspected for JSON shape only. Each question credits a conceptual chapter and primary verification; that credit does not mean the new scenario appeared in the source video.

The 63-question / 120-minute format, seven weights, and 38 local objective labels come from the supplied CCAR-P v1 July 2026 guide reference. The guide registry link is its official directory, not a public copy of the supplied attachment. The particular 38 single / 21 select-two / 4 select-three mix is this practice design. The source videos’ 46/63 study target is not an official pass conversion; a scaled score cannot be translated into an endorsed 72% raw threshold here. No live exam, dump, recalled actual question, or booking-readiness claim is made. Difficulty is intended to challenge architectural transfer but has not been calibrated against the live examination or candidate outcomes.

## Independent numerical proofs

1. Q10: A = 120 × $40 − $900 = $3,900 monthly capacity value. B = 180 × $40 − $2,200 = $5,000. B exceeds A by $1,100. This is valued usable capacity, not assumed payroll reduction.
2. Q12: R passes 94% factual acceptance and 1.8-second p95 gates; P fails quality and Q fails latency. This is a feasibility comparison, not averaging of independent gates.
3. Q24: A passes 92% coverage and 3.0-second p95 gates; B fails latency. Percentiles of configurations cannot simply be averaged into a proven mixed-service percentile.
4. Q32: recall = 30/40 = 75%; precision = 30/50 = 60%; accuracy = (30+940)/1000 = 97%. Recall misses 80%, despite passing 55% precision.
5. Q40: original = 18 × 700 = 12,600; proposed = 7 × 700 + 300 = 5,200; net reduction = 7,400 input-equivalent tokens under the stipulated accounting.
6. Q52: 24,000 requests / 10 minutes × 2 calls = 4,800 calls/minute. Provision = 3,000. Deficit = 1,800 calls/minute, or 18,000 over ten minutes. Bursts and other limits are intentionally not assumed away for a real commitment.

The arithmetic for Q10, Q32, Q40, and Q52 was recomputed in independent Python assertions after the prose and answer choices were written.
