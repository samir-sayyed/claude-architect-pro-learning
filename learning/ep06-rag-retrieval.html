01 / UNDERSTAND

Five ideas worth keeping.

Chunking is a meaning-preservation decision.

Fixed-size chunks are simple but may cut an argument or clause. Semantic chunks follow topic changes. Structure-aware chunks respect headings, sections, tables, and legal clauses. Choose the boundary that preserves the relationships your questions depend on.

↗ Lesson 10:00

A fragment needs enough identity to stand alone.

A chunk saying revenue grew by three percent is ambiguous without the company and period. Contextual information can make a fragment interpretable before it is indexed. Preserve source identity and metadata so the answer can remain tied to the right document.

↗ Lesson 17:00

Semantic similarity and exact matching solve different problems.

Vector retrieval helps with related meanings. Keyword retrieval helps with contract numbers, names, and exact terms. Hybrid retrieval can combine them; metadata narrows the scope by date, document, tenant, or access context. Select based on query behavior.

↗ Lesson 20:00

More retrieved text is not automatically better evidence.

Reranking can reduce a broad candidate pool to a smaller, more useful set. That adds a step but can improve the signal passed to the generator and reduce context waste. Judge it against quality and latency, not simply the number of chunks returned.

↗ Lesson 28:00

After a corpus refresh, inspect retrieval before changing the model.

Look for stale embeddings, missing re-indexing, lost metadata, index synchronization failures, or parsing changes. If the correct evidence never reaches the model, a stronger model may only produce a more convincing unsupported answer.

03 / WORKED EXAMPLE · FROM THE LESSON

A contract question gets a generic answer

In the lesson’s legal-document scenario, a question about one contract retrieves generic termination language rather than the relevant clause and its conditions.

THE TEMPTING MOVE

Add a larger context window or ask the model to reason harder over the same weak evidence.

THE BETTER-FITTING MOVE

Preserve clause structure, add document identity, use exact-match signals alongside semantic retrieval, and filter to the intended contract. Inspect the retrieved evidence before judging generation.

The bottleneck is evidence selection. Generation can only be grounded in the material it receives.

DETAIL 01

Keep the offline and online halves distinct

The deck’s baseline has seven stages. Reranking is an optional additional online stage, which the interactive map calls out separately. Indexing quality limits what can be retrieved; generation cannot reliably reconstruct evidence that never reaches it.

  1. Offline: ingest → chunk → embed → index
  2. Online: process query → retrieve → generate
  3. Optional online refinement: retrieve candidates → rerank → select context → generate
  4. Preserve source identity and access metadata across both halves.

DETAIL 02

Make an isolated chunk understandable

A fragment saying “revenue grew by 3%” loses company and period. Preserve headings, document identity, and a concise context prefix where appropriate. Dense retrieval helps meaning, sparse retrieval helps exact identifiers, hybrid combines their signals, and metadata scopes documents by tenant, date, or type. Benchmark the combination on your queries; no strategy wins universally.

DETAIL 03

Understand what the teaching demo actually implements

The repository uses three policy documents, a fixed-size character chunker with overlap, TF-IDF vectors, cosine similarity, and source-labeled context for generation. Fit TF-IDF on the corpus and transform queries with the same vocabulary. The sample uses 200-character chunks and 50-character overlap, so successive starts are 150 characters apart. Characters are not tokens, and overlap alone does not guarantee intact sentences. This is a small retrieval demonstration, not a production dense-vector service.

DETAIL 04

After a refresh, inspect the evidence path

Hold a failing query fixed and compare the retrieved chunks and versions with the last good run. A correct query embedding cannot compensate for obsolete records, broken boundaries, or incompatible index updates. Repair and re-evaluate the failing stage before changing the generator.

Symptom mechanismEvidence to inspect
Old and new versions competeDocument IDs, version metadata, deletion/update behavior

Dense and sparse paths disagreeCorpus/index versions and update completeness
New document format breaks splittingParsed structure and chunk boundaries
